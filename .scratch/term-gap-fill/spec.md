# 規格:術語補標與漏標稽核

Status: ready-for-agent

## 需要你決定的

### 技力回復的稽核種子字怎麼定?

稽核原型寫好之後,才新增了「技力回復」這個補充關鍵字,所以原型的種子字沒有它。技力回復的比對字串是精細列舉的寫法(「點技力」「技力+」等)。「技力」本身很常見,但拿來當種子字,目前只掃出 18 種前後文(算法見[其他備註](#其他備註))。裡面有誤中,例如「技力滿時」「阻擋敵人時才能夠回復技力」;也有疑似真的漏標,例如繆爾賽思「立刻獲得#技力」。

決定(2026-11-09):技力回復用「技力」當種子字,現有誤中收進已知清單;補充關鍵字沒寫種子字時,建置發警告。

- (a)技力回復用「技力」當種子字,現有誤中收進已知清單;以後新增補充關鍵字卻沒寫種子字時,建置發警告(建議):每個補充關鍵字都有稽核,新增時不會忘了寫種子字。
- (b)種子字可以省略,沒寫的補充關鍵字就不稽核;技力回復先不寫:清單較短,但技力回復的新寫法要等玩家回報。

### 補標讓台服與陸服變成一致時,要不要防既有判定改變?

建置時,台服文字的標記結果和陸服一致,就沿用陸服的效果類型,不再查台服自己的覆寫判定;陸服模式也會改顯示繁中。這是現有規則。補標之後,原本只因台服少標而不一致的敘述會變成一致,改走這條路。用目前資料模擬,沒有任何既有關鍵字的效果類型改變。但這只是資料剛好如此:如果某段敘述的台服覆寫和陸服覆寫不同,台服模式的效果類型就會悄悄改成陸服的。

決定(2026-11-09):建置時檢查,台服原有覆寫判定與陸服不同就發建置警告。

- (a)建置時檢查:變成一致的敘述,如果台服原有的覆寫判定和陸服不同,就發建置警告(建議):以後加比對字串時也有保障,程式多一點。
- (b)只在這次實作時核對一次,比較補標前後全部既有配對的效果類型:不加程式,但以後加比對字串時沒有保障。
- (c)不處理:接受沿用陸服判定,兩服判定不同的情況很少見。

### 用什麼機制補上遊戲沒標的術語?

決定(2026-11-09):術語純文字比對清單。

- 術語純文字比對清單(建議):跟補充關鍵字同一套作法,由維護者列出哪些術語也要比對純文字。兩種漏標都補得到;同名術語(敵方版與「·我方」版)只能排除。
- 台服沿用陸服標記,加上術語純文字比對清單:同名術語也分得對,但要維護兩套機制。
- 只做台服沿用陸服標記:全自動、最精準,但兩服都沒標的補不到。
- 逐段補標檔:以文字雜湊指定標記,最精準,但每段都要手動處理,上游文字一改就失效。

### 稽核腳本要不要納入資料更新流程?

決定(2026-11-09):納入,並加進 /update-data 的步驟。

- 納入(建議):每次更新資料都列出疑似漏標。
- 不納入:需要時再重寫一次。

### 術語比對清單放在哪裡?

決定(2026-11-09):新的維護者清單,只放術語 id 與兩服的比對字串。

- 新的維護者清單(建議):名稱與定義沿用官方的,每筆欄位一致。
- 併進補充關鍵字清單:同一個檔裡兩種項目的必填欄位不同。

### 已經有官方標記的敘述,重複出現的同名術語也要標嗎?

決定(2026-11-09):每個沒標的地方都標。

- 每個沒標的地方都標(建議):高亮一致,和補充關鍵字的比對方式相同。
- 只補整段完全沒標到該術語的敘述:改動範圍最小。

### 一開始要收哪些術語?

決定(2026-11-09):只收這次確實漏標的 13 個,另收 4 個較長的同字術語名稱防止誤標。

- 只收確實漏標的(建議):有證據才收,之後稽核掃到新的漏標再加。
- 所有術語都收,只排除會出問題的:以後的新資料也能自動補,但誤中多、複核負擔重。

### 詞彙表怎麼描述?

決定(2026-11-09):只改「術語」的定義,不新增詞。已寫進 GLOSSARY.md。

- 只改「術語」的定義(建議):補上的仍是同一個術語。
- 新增一個詞(例如「補標」)。
- 詞彙表不改。

### 稽核每次都列出已知的誤中嗎?

決定(2026-11-09):建一份已知清單,只列新出現的,並提供指令把這次結果收進已知清單。

- 已知清單,只列新的(建議):和已知警告清單同一套作法。
- 每次列出全部:沒有額外檔案,但每次都要從頭看。

### 稽核在什麼時候跑?

決定(2026-11-09):併進建置索引。

- 併進建置索引(建議):和警告、待複核清單一起輸出,流程最少一步。
- 獨立指令,再寫進 /update-data。

## 問題陳述

玩家點一個關鍵字,期望列出所有有這個效果的幹員。但有些幹員明明有這個效果,卻沒有出現在結果裡,原因有兩種:

- **遊戲沒有加術語標記。** 術語靠遊戲文字裡的官方標記辨識,上游資料有時漏標,分兩種:
  - 台服翻譯少了標記、陸服有標:例如裁度的技能,陸服把「束缚」標成束縛,台服的「束縛」只是純文字,所以台服模式搜「束縛」找不到裁度;琴柳、斥罪、烏爾比安的「暈眩」也一樣。
  - 兩服都沒標:例如許多幹員特性裡的「可以造成元素損傷」,這些幹員搜「元素損傷」時就缺了特性這一段。有時漏的只是幹員的其中一段敘述,幹員本身靠別段搜得到,但結果卡上不會列出漏標的那段,例如三角初華另一段敘述裡的「鼓舞效果」。
- **補充關鍵字的比對字串沒涵蓋新寫法。** 例如阿米婭(術師)3 技能寫「傷害類型變為真實」,不是「真實傷害」。這類漏掉的寫法已經在本規格之前補完,但目前沒有任何機制能在下次資料更新時發現新的寫法。

維護者目前只能靠玩家回報,或自己寫一次性的腳本去掃。

## 解決方案

兩件事:

1. **術語補標**:新增一份維護者清單「術語比對清單」,列出某些術語在兩服的比對字串。建置時,這些字串在敘述純文字中沒被標記的地方,一律標成該術語,跟補充關鍵字的比對方式相同。補上的仍算同一個術語,用官方定義,玩家看不出差別,只是搜得到了。新命中的配對照現有流程進待複核清單。
2. **漏標稽核**:建置索引時一併掃描,找出「文字裡寫了某個效果、但整段敘述沒標到這個關鍵字」的地方,列為疑似漏標。已知的誤中(例如地名「拉特蘭」裡的「拉」)記在已知清單,之後只列新出現的。/update-data 多一步:看新的疑似漏標,由維護者決定要補比對字串,還是收進已知清單。

## 使用者故事

1. 身為玩家,我想在台服模式搜「束縛」時看到裁度,這樣台服翻譯漏標不會讓我漏看幹員。
2. 身為玩家,我想在台服模式搜「暈眩」時看到琴柳、斥罪、烏爾比安,也在凱爾希、提豐的結果卡看到漏標的那幾段敘述,這樣台服的搜尋結果和陸服一致。
3. 身為玩家,我想在台服模式搜「迷彩」時看到忍冬,這樣台服漏標的效果也找得到。
4. 身為玩家,我想在搜「元素損傷」時看到特性寫「可以造成元素損傷」的幹員,這樣搜尋結果不會缺一整批幹員。
5. 身為玩家,我想讓補標的字和官方標記的字高亮方式一樣、點了一樣顯示官方定義,這樣我分不出也不需要分出哪些是補的。
6. 身為玩家,我想讓同一段敘述裡重複出現的同一個術語都高亮,這樣不會一個亮、一個不亮,讓我以為是錯誤。
7. 身為玩家,我想讓「法術脆弱」「物理護盾」這類較長的術語不被誤標成「脆弱」「護盾」,這樣搜「脆弱」不會混進法術脆弱的幹員。
8. 身為玩家,我想讓補標後新列入的敘述也有正確的效果類型(施加、利用、反制),這樣依效果類型搜尋時結果是對的。
9. 身為玩家,我想讓補標不改變原本已經搜得到的敘述的效果類型,這樣既有的搜尋結果不會突然變動。
10. 身為維護者,我想用一份清單決定哪些術語要比對純文字、比對哪些字串,這樣誤中風險高的術語(例如「移動」)可以不收。
11. 身為維護者,我想讓清單每筆只寫術語 id 和兩服的比對字串,這樣不用重抄官方名稱與定義。
12. 身為維護者,我想讓陸服與台服的比對字串分開寫,這樣簡繁不同的寫法都比對得到。
13. 身為維護者,我想讓清單裡寫錯的術語 id(不是遊戲術語、不是戰鬥術語,或是不當關鍵字的術語)在建置警告裡列出,這樣筆誤不會默默失效。
14. 身為維護者,我想讓補標新命中的配對進待複核清單(補標後台服與陸服一致的,台服沿用陸服判定,不另外列),這樣誤中可以在複核時判成沒有效果類型擋掉。
15. 身為維護者,我想讓術語比對清單和補充關鍵字一起依字串長度比對、較長的優先,這樣兩份清單的字串互相重疊時結果可預期。
16. 身為維護者,我想在建置摘要看到「疑似漏標」的總數與新出現的則數,這樣更新資料時一眼知道有沒有新的寫法要處理。
17. 身為維護者,我想讓疑似漏標只列「整段敘述完全沒標到該關鍵字」的地方,這樣遊戲只標第一次出現、後面不標的情況不會成為雜訊。
18. 身為維護者,我想讓已經標成其他關鍵字的字不列為疑似漏標,這樣「法術脆弱」裡的「脆弱」不會被當成漏標。
19. 身為維護者,我想讓同名術語(敵方版與「·我方」版)在稽核時視為同一個,這樣整段已標了其中一個時不會被列為漏標。
20. 身為維護者,我想讓稽核的術語部分自動用每個術語在兩服的官方名稱,這樣遊戲新增術語時不用另外設定。
21. 身為維護者,我想用一份維護者清單設定每個補充關鍵字的稽核種子字(例如推:「推」「擊退」),這樣能掃到比對字串以外的新寫法。
22. 身為維護者,我想在新增補充關鍵字卻忘了寫種子字時看到建置警告,這樣每個補充關鍵字都有稽核。
23. 身為維護者,我想在補標讓某段敘述的台服與陸服變成一致、而台服原有的效果類型判定和陸服不同時看到建置警告,這樣既有判定不會悄悄改變。
24. 身為維護者,我想讓每則疑似漏標附上伺服器、關鍵字、前後文、命中的種子字、涉及的幹員和第一個出處,這樣不用回頭翻資料就能判斷是漏標還是誤中。
25. 身為維護者,我想讓前後文裡的數字換成同一個符號,這樣同一種寫法在不同等級的數值不同,也只算一則。
26. 身為維護者,我想讓同一種前後文在多位幹員出現時合成一則、列出全部幹員,這樣清單不會被同一種寫法洗版。
27. 身為維護者,我想把確認是誤中的疑似漏標收進一份納入版控的已知清單,這樣下次建置不再列出。
28. 身為維護者,我想用一個指令把這次的疑似漏標全部收進已知清單,並移除已經不再出現的,這樣不用手抄。
29. 身為維護者,我想看到已知清單裡有、這次沒出現的疑似漏標,這樣知道哪些被補標或上游修好了。
30. 身為維護者,我想在 /update-data 裡讓 agent 逐則判斷新的疑似漏標是漏標還是誤中,並列給我確認,這樣我只需要做決定。
31. 身為維護者,我想在確認是漏標後,讓 agent 把比對字串加進術語比對清單或補充關鍵字清單,再重新建置、複核新配對,這樣補漏和平常的更新流程一樣。
32. 身為維護者,我想讓疑似漏標和建置警告的已知清單用同一種比對方式,這樣兩套流程的行為一致、好記。
33. 身為維護者,我想讓 README 說明術語比對清單、稽核種子字、已知清單和收進已知清單的指令,這樣不在 session 時也能手動處理。

## 實作決策

- **術語比對清單**:新的維護者清單,納入版控。每筆是術語 id 加上陸服與台服各自的比對字串列表。建置索引的輸入多這一份。
- **一開始的內容**:下表 13 個確實漏標的術語,加上 4 個較長的同字術語(法術脆弱、物理脆弱、元素脆弱、物理護盾)。比對字串就是各術語在兩服的官方名稱。

| 術語 id | 陸服 | 台服 |

| ba.root | 束缚 | 束縛 |
| ba.levitate | 浮空 | 浮空 |
| ba.frozen | 冻结 | 凍結 |
| ba.sluggish | 停顿 | 停頓 |
| ba.shield | 护盾 | 護盾 |
| ba.camou | 迷彩 | 迷彩 |
| ba.debuff | 异常状态 | 異常狀態 |
| ba.fragile | 脆弱 | 脆弱 |
| ba.invisible | 隐匿 | 隱匿 |
| ba.inspire | 鼓舞 | 鼓舞 |
| ba.permanentatk | 持续攻击 | 持續攻擊 |

- **比對**:術語比對清單與補充關鍵字清單的字串合在同一輪比對,規則沿用補充關鍵字:在整段純文字上比對(可跨越樣式標記),較長的字串優先,已有標記(官方術語標記或先比對到的)的字不重疊標記。補上的標記和補充關鍵字一樣不保留原本的樣式。同 補充關鍵字。
- **清單驗證**:清單裡的 id 必須是會成為關鍵字的戰鬥術語(ba. 開頭)而且不在不當關鍵字的術語清單裡;不符合時建置發出警告,這筆不比對。非戰鬥術語(例如基建、陣營詞)依詞彙表不是關鍵字,不能經由補標變成關鍵字。
- **效果類型**:補上的標記和官方標記走同一條路:先查覆寫檔,沒有就用規則判定,並列入待複核清單。覆寫檔以敘述純文字的雜湊為鍵,補標不改純文字,所以在兩服一致與否不變的敘述上,已複核過的「敘述 × 關鍵字」配對判定不變。
- **台服與陸服一致的判斷**:現有的「台服文字與陸服一致就沿用陸服效果類型」比較的是標記後的結果,兩服都經過補標後再比較,規則本身不改。原本只因台服少標而不一致的敘述,補標後會變成一致:台服改沿用陸服的效果類型,這些台服配對不進待複核清單,陸服模式改顯示繁中。為了防止既有判定因此悄悄改變(見[補標讓台服與陸服變成一致時,要不要防既有判定改變?](#補標讓台服與陸服變成一致時,要不要防既有判定改變?)):兩服一致時,建置仍以台服純文字的雜湊查台服的覆寫判定,只要有任何一個關鍵字的台服覆寫和沿用來的陸服效果類型不同,就發建置警告,指出幹員、出處、關鍵字與兩邊的判定。效果類型照樣沿用陸服的。
- **漏標稽核**:建置索引的輸出多一份「疑似漏標」清單,和警告、待複核清單並列。對每一段敘述的每個伺服器文字各掃一次,兩種檢查:
  - 術語:只掃會成為關鍵字的戰鬥術語(ba. 開頭、不在不當關鍵字的術語清單裡),用它們在兩服的官方名稱,去掉「·我方」後綴。同名術語(id 只差結尾的 2,例如凋亡損傷與凋亡損傷·我方)合成一組只掃一次,疑似漏標記在不帶 2 的那個 id 名下。
  - 補充關鍵字:用稽核種子字清單。
- **疑似漏標的條件**:種子字出現的位置沒有任何標記,而且這段敘述在這個伺服器的文字裡,沒有任何地方標成該關鍵字或它的同名術語。
- **疑似漏標的內容與合併**:前後文取命中處前 8 個字、種子字本身、後 8 個字,再把連續的數字與小數點(連同緊接在後的「%」)換成一個「#」,換行換成「⏎」。伺服器、關鍵字、前後文三者相同的合成一則,記錄命中的種子字、涉及的幹員 id 與第一個出處。這三者組成的字串就是這則的識別鍵,已知清單以它比對。與已知警告不同:已知警告以全文比對,這裡的識別鍵不含幹員與出處,新幹員出現已知的誤中寫法不會再報(2026-11-09 選定)。
- **稽核種子字清單**:新的維護者清單,納入版控,每個補充關鍵字 id 對應一組種子字(兩服的字寫在一起)。初始內容:
  - 真實傷害:真實、真实(不用「無視」,無視防禦不是真實傷害)。
  - 推:推、擊退、击退。
  - 拉:拉、拖、牽引、牵引、吸。
  - 沉默:沉默、特殊能力、無法使用技能、无法使用技能、封印。
  - 減速:移動速度、移动速度、減速、减速、移速。
  - 閃避:閃避、闪避、躲避、迴避、回避、躲閃、躲闪。
  - 技力回復:技力(見[技力回復的稽核種子字怎麼定?](#技力回復的稽核種子字怎麼定?))。
- **種子字驗證**:補充關鍵字清單裡有、稽核種子字清單裡沒有(或種子字是空的)的補充關鍵字,建置發警告;種子字清單裡的 id 不是補充關鍵字時也發警告。
- **已知清單比對**:把現有的已知警告比對改成通用的純函式,輸入目前清單與已知清單,輸出新出現的與已消失的。警告與疑似漏標共用。同 已知警告。
- **已知疑似漏標清單**:新的維護者清單,納入版控,內容是識別鍵的列表。建置寫出全部疑似漏標、新的疑似漏標、已消失的已知疑似漏標三份檔案,放在 review 資料夾。另外新增一個維護者指令,把已知清單改成這次全部疑似漏標的識別鍵,作法同收進已知警告的指令。同 已知警告(三份 review 檔、另一個收進已知清單的指令)。
- **建置摘要**:多一行疑似漏標的總數、新出現的則數與已消失的則數;有新的時印出前 10 則。同 已知警告的摘要格式。
- **/update-data**:在新警告那一步之後加一步。agent 讀新的疑似漏標,逐則判斷是漏標還是誤中並附理由,**停下**列給維護者。維護者確認後:漏標的把比對字串加進術語比對清單或補充關鍵字清單、離線重建、照效果類型複核那一步複核新配對;其餘執行收進已知清單的指令,再離線重建。完成條件:建置摘要的新疑似漏標與已消失的都是 0 則。同 新警告那一步的停下確認方式。
- **README**:「更新遊戲資料」與建置輸出的說明補上術語比對清單、稽核種子字清單、已知疑似漏標清單、三份 review 檔與新指令。

## 測試決策

- 好的測試只看外部行為:給定原始資料與維護者清單,檢查搜尋結果與建置輸出,不測內部怎麼比對。已知清單比對本身就是對外的純函式,直接測它。
- **術語補標**:從建置索引切入、用查詢檢查,前例是現有的補充關鍵字測試。案例包括:
  - 純文字的術語名稱被補標,查該術語找得到,高亮該字。
  - 台服沒標、陸服有標時,台服模式也找得到。
  - 已有官方標記的敘述裡,重複出現的同名術語也被標。
  - 較長的術語(法術脆弱)優先,不被標成脆弱。
  - 已有官方標記的字不重複標。
  - 清單裡寫錯的 id(不存在的術語、非戰鬥術語、不當關鍵字的術語)產生建置警告,而且沒有被補標。
  - 新命中的配對出現在待複核清單(用兩服補標後仍不一致的敘述,或只有陸服的資料)。
  - 台服只因少標而與陸服不一致的敘述,補標後台服沿用陸服的效果類型。
  - 同上的敘述,台服原有覆寫判定與陸服不同時發建置警告;相同時不發。
- **漏標稽核**:從建置索引的輸出檢查疑似漏標清單。案例包括:
  - 純文字的術語名稱、整段沒標到該術語,會被列出。
  - 整段已標過該術語(只是重複出現處沒標),不列出。
  - 整段已標過同名的「·我方」術語,不列出;同名術語的同一處漏標只列一則。
  - 非戰鬥術語與不當關鍵字的術語不掃。
  - 補充關鍵字沒寫種子字、或種子字清單有不存在的補充關鍵字時,發建置警告。
  - 種子字落在其他關鍵字的標記內,不列出。
  - 補充關鍵字的種子字沒被標到,會被列出。
  - 數字不同的同一種前後文合成一則,涉及的幹員全部列出。
- **已知清單比對**:現有警告比對的測試改寫成測通用函式(案例不減),再加一組疑似漏標識別鍵的案例。
- **建置指令的讀寫檔、收進已知清單的指令、/update-data 的步驟**:不寫自動測試,跟現狀一樣;實作後實際跑一次建置驗證。
- 除了上一項改寫的警告比對測試,現有的單元測試與 e2e 煙霧測試全部要原樣繼續通過。

## 不在範圍內

- 同名術語的補標:凋亡損傷(敵方版與「·我方」版)只看文字分不出,不收進術語比對清單。已知受影響:PhonoR-0、菲萊的台服凋亡損傷。
- 台服沿用陸服標記的機制。
- 「移動」「蓄力」「屏障」這類誤中風險高、或沒有確實漏標證據的術語。之後稽核掃到確實漏標再加。
- 讓 LLM 逐筆讀完全部敘述找漏標。稽核只找得到含種子字的寫法,完全換句話說的找不到。
- 介面改動:補標的字和官方標記的字看起來一樣。
- 補充關鍵字比對字串的補漏(真實傷害、推、拉、沉默、減速),已在本規格之前完成。

## 其他備註

- 稽核的原型是這次 session 在 scratchpad 寫的一次性腳本 audit.cjs(用法:在 repo 根執行 node audit.cjs .)。它從建好的幹員檔讀資料,正式版改成在建置索引時用剛標好的敘述計算;判斷條件與前後文格式以本規格的實作決策為準。
- 「確實漏標的 13 個術語」:原型輸出 A 段出現的術語,扣掉不收的移動、屏障、蓄力、凋亡損傷(兩個 id)。「4 個較長的同字術語」:沒被排除的戰鬥術語裡,名稱包含那 13 個名稱的只有表格最後 4 個;它們目前在純文字中沒有出現,純屬預防(scratchpad 的 speccheck.cjs,在 repo 根執行 node speccheck.cjs . longer)。兩個數字在 2026-11-09 標 ready-for-agent 前重跑核對過。

- 台服模式在技能、天賦、特性的非模組階段看台服文字的標記;模組階段兩服都用陸服文字,所以台服少標只影響非模組階段。
