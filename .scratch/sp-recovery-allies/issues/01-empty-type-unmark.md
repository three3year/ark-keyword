# 01: 空類型的補充關鍵字配對不標記

**What to build:** 某段敘述對某補充關鍵字的最終效果類型(覆寫優先,否則用規則判定)為空時,這段敘述裡這個關鍵字的標記全部拿掉,變回純文字:幹員詳情與結果卡都沒有虛線底、沒有定義提示;同時選了多個關鍵字時,結果卡也不高亮它。台服文字與陸服一致時,台服沿用陸服的判定,兩份文字一起拿掉;拿掉標記不改變「兩服是否一致」的判斷,一致的台服配對也不因此進待複核。術語照舊標記。漏標稽核把這種敘述視為已處理,不列該關鍵字的疑似漏標。目前沒有任何補充關鍵字的配對是空類型,所以實際索引不變。規格見 `.scratch/sp-recovery-allies/spec.md`。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] Vitest(建置 → 查詢):某段敘述對某補充關鍵字的覆寫是空類型時,索引文字裡這個關鍵字不標記、查詢不列入;同一個關鍵字在另一段敘述覆寫為施加時照樣標記並列入
- [ ] Vitest:術語的空類型配對照舊標記
- [ ] Vitest:規則判定為空、還沒複核的補充關鍵字配對同樣不標記,仍列入待複核
- [ ] Vitest:台服文字與陸服一致、陸服覆寫為空類型時,兩服文字都不標記,該階段仍判為兩服一致,台服配對不進待複核
- [ ] Vitest(稽核):空類型而拿掉標記的敘述不列該關鍵字的疑似漏標;另一段沒標到、含種子字的敘述照樣列
