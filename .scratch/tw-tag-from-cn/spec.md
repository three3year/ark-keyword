# 規格:照陸服標記補台服

Status: ready-for-agent

## 需要你決定的

### 台服漏標而陸服有標的術語,用什麼方式補?

決定(2026-11-09):照陸服的標記補台服,所有術語都適用。

- (a)照陸服的標記補台服,所有術語都適用(建議):陸服有、台服沒標的術語,用它的台服官方名稱在台服純文字裡找,找到就標成陸服的 id。台服文字裡沒有這個名稱就不標,台服是舊版文字時不會誤列。缺點是多一套機制,和術語比對清單並存。
- (b)同 (a),但只用在同名術語:適用範圍最小,但要另外判斷哪些算同名術語;以後其他術語在台服漏標,還是要手動加進比對清單。
- (c)陸服判定是否命中,台服只負責顯示:台服文字沒有對應的字可以高亮,台服是舊版文字時也可能列出台服還沒有的效果。
- (d)不做:接受 PhonoR-0 和菲萊在台服模式搜「凋亡損傷」時找不到。

### 台服文字裡同一個名稱出現好幾次,要標哪些?

決定(2026-11-09):全部沒標的地方都標;同一名稱對到不同 id 時不標,並發建置警告。

- (a)全部沒標的地方都標;同一名稱對到不同 id 時不標並發建置警告(建議):和術語比對清單「每個沒標的地方都標」一致;分不出哪個位置對哪個 id 時交給維護者。
- (b)依出現順序一一對應:同名不同 id 也能自動處理,但兩服語序可能不同,對錯位置時看不出來。
- (c)只標第一次出現:改動最少,但同一段敘述會一處亮、一處不亮。

### 陸服有標、台服文字卻找不到這個名稱時,要不要發建置警告?

決定(2026-11-09):發建置警告。

- (a)發建置警告(建議):維護者知道哪裡兩服不一致;台服是舊版文字時會一直報,可以收進已知警告清單。
- (b)不發:這段敘述照舊用台服自己的標記。

### 詞彙表「術語」的定義怎麼改?

決定(2026-11-09):寫明兩種補法。已寫進 GLOSSARY.md。

- (a)「遊戲漏標的地方會補上:台服漏標而陸服有標的,照陸服的標記補;其餘由維護者清單比對純文字補上。補上的仍算同一個術語,用官方定義。」(建議)
- (b)不分來源:「遊戲漏標的地方會補上,補上的仍算同一個術語,用官方定義。」
- (c)維持現狀。

## 問題陳述

玩家在台服模式點「凋亡損傷」,PhonoR-0 和菲萊沒有出現在結果裡,但陸服模式找得到。兩人天賦 1 的台服文字都寫了「凋亡損傷」,只是遊戲沒有加術語標記;陸服有標,PhonoR-0 標的是我方版(凋亡損傷·我方),菲萊標的是敵方版。

術語補標與漏標稽核(見[其他備註](#其他備註))用術語比對清單補上了其他漏標,但補不了這兩段:敵方版與「·我方」版在台服的名稱都是「凋亡損傷」,只看台服文字分不出該標成哪一個。那份規格因此把同名術語的補標和「台服沿用陸服標記的機制」列為不在範圍內。

目前全部資料裡,台服與陸服的標記不一致的敘述只剩這 2 段(在 repo 根執行 `node <scratchpad>/cmp.cjs .`,見[其他備註](#其他備註))。

## 解決方案

建置時,陸服有標、台服沒標的術語,照陸服的標記補到台服:用這個術語的台服官方名稱在台服純文字裡找,找到就標成陸服的那個 id。標記的 id 來自陸服,所以同名術語也分得對。補完後兩服一致,照現有規則,台服沿用陸服的效果類型,陸服模式改顯示繁中。玩家看不出差別,只是台服模式搜得到、也會高亮。

台服文字裡找不到這個名稱,或同一個名稱對到陸服兩個不同的 id 時,不標,發建置警告,交給維護者判斷。

## 使用者故事

1. 身為玩家,我想在台服模式搜「凋亡損傷」時看到 PhonoR-0 和菲萊,這樣台服漏標不會讓我漏看幹員。
2. 身為玩家,我想讓 PhonoR-0 的凋亡損傷算成我方版、菲萊的算成敵方版,這樣台服的結果和陸服一樣,不會把兩種效果混在一起。
3. 身為玩家,我想讓照陸服補上的字和官方標記的字高亮方式一樣、點了一樣顯示官方定義,這樣我分不出也不需要分出哪些是補的。
4. 身為玩家,我想讓同一段台服敘述裡重複出現的同一個術語都高亮,這樣不會一個亮、一個不亮。
5. 身為玩家,我想讓台服模式的效果類型(施加、利用、反制)和陸服一致,這樣依效果類型搜尋時兩服結果相同。
6. 身為玩家,我想讓台服還是舊版文字的敘述,不會因為陸服改版而在台服模式列出台服還沒有的效果,這樣台服模式反映的是台服的遊戲內容。
7. 身為陸服模式的玩家,我想讓補完後與陸服一致的敘述照現有規則改顯示繁中,這樣顯示方式和其他一致的敘述相同。
8. 身為玩家,我想讓召喚物的敘述也照陸服補標,這樣召喚物的效果在台服模式一樣搜得到。
9. 身為維護者,我想讓台服以後又漏標陸服有標的術語時自動補上,這樣不用等稽核掃到、再手動加進術語比對清單。
10. 身為維護者,我想在陸服有標、台服文字卻找不到這個術語的台服名稱時看到建置警告,這樣翻譯換了說法的漏標也找得到。
11. 身為維護者,我想讓這種警告能收進已知警告清單,這樣台服是舊版文字的敘述在台服更新前不會一直出現在新警告裡。
12. 身為維護者,我想在同一個台服名稱對到陸服兩個不同 id 時看到建置警告、而且不被自動標上,這樣不會猜錯位置標錯 id。
13. 身為維護者,我想讓照陸服補標不需要任何清單或設定,這樣遊戲新增術語時不用另外維護。
14. 身為維護者,我想讓補完後兩服一致的敘述照現有規則沿用陸服判定、不另列待複核,這樣複核量不會增加。
15. 身為維護者,我想讓台服原有覆寫判定與陸服不同時照樣發建置警告,這樣既有判定不會因為補標悄悄改變。
16. 身為維護者,我想讓已知疑似漏標清單裡因此補好的項目在建置摘要顯示為已消失,並在實作時收進已知清單,這樣清單與現況一致。

## 實作決策

- **在哪裡做**:建置索引組成一個階段時,台服文字解析完、比對術語比對清單與補充關鍵字之前,先照陸服補標。只對有台服文字的階段做;模組階段兩服都用陸服文字,不受影響。召喚物的敘述走同一條流程,一樣適用。
- **找出要補的術語**:兩服都只數官方標記,也就是比對術語比對清單與補充關鍵字之前的標記;以標記數計,同一個標記因樣式拆成幾段也只算一次。陸服這段敘述某個 id 的標記數多於台服的,就是要補的 id。陸服因排除清單而不帶標記的術語不算。只由術語比對清單補上的術語不算陸服有標,所以兩服都沒標的漏標照舊只靠比對清單補,高亮範圍不變。
- **台服名稱**:台服官方術語名稱,去掉「·我方」後綴(去後綴的方式同漏標稽核)。台服資料沒有這個術語時,這個 id 不補。
- **標記方式**:在台服整段純文字上找這個名稱,所有還沒有任何標記的出現處都標成該 id;可跨越樣式標記,已有標記的字不重疊標,補上的標記不保留原本的樣式。同 術語比對清單的比對方式。
- **同名不同 id**:要補的 id 裡有兩個以上的台服名稱相同時,這個名稱一處都不標,發建置警告,指出幹員、出處、名稱與兩個 id。
- **找不到名稱**:在全部標記完成之後判斷(照陸服補標、術語比對清單、補充關鍵字都做完)。某個 id 在台服的最終標記數仍少於陸服官方標記數時,發建置警告,指出幹員、出處與 id。照陸服補標找不到、但比對清單補上了的,不算缺,不發。已經因同名不同 id 發過警告的 id 不再重複發。警告走現有的已知警告機制。
- **補完之後**:接著照現有流程比對術語比對清單與補充關鍵字,再判斷兩服是否一致。一致的規則不改:台服沿用陸服的效果類型,陸服模式改顯示繁中,台服覆寫判定與陸服不同時發建置警告。仍不一致的,台服照現有流程自行判定並列入待複核。
- **疑似漏標稽核**:稽核掃的是補完標記後的台服文字,照陸服補好的地方不再列出,不另外改稽核。已知疑似漏標清單裡 PhonoR-0 與菲萊的 2 筆(`grep -c "tw ba.dt.apoptosis " data/known-suspects.json`)會變成已消失;實作後執行收進已知清單的指令,再離線重建。
- **詞彙表**:「術語」的定義已改,見[詞彙表「術語」的定義怎麼改?](#詞彙表「術語」的定義怎麼改?)。

## 測試決策

- 好的測試只看外部行為:給定兩服原始資料,檢查搜尋結果、高亮、建置警告與待複核清單,不測內部怎麼補標。
- 切入點只有一個:從建置索引切入、用查詢檢查,前例是術語補標的測試。不新增切入點。
- 案例:
  - 台服純文字有該術語的台服名稱、陸服有標:台服模式查得到,該字高亮成陸服的 id。
  - 同名術語:陸服標我方版的,台服標成我方版;陸服標敵方版的,台服標成敵方版。
  - 同一段台服文字裡同一個名稱出現多次,全部標上。
  - 同一個台服名稱對到陸服兩個不同 id:不標,發建置警告。
  - 台服文字找不到該名稱(用詞不同,或台服資料沒有這個術語):不標,發建置警告。
  - 照陸服補標找不到、但術語比對清單補上了:不發警告。
  - 只由術語比對清單補上、陸服沒有官方標記的術語:不照陸服補,台服高亮範圍照比對清單。
  - 補完後兩服一致:台服沿用陸服的效果類型,台服的配對不另列待複核;陸服模式顯示台服文字。
- 召喚物的敘述不另寫測試:和幹員本身走同一個產生階段的流程。
- 現有的單元測試與 e2e 煙霧測試全部要原樣繼續通過。實作後實際跑一次建置,確認新警告為 0 則、PhonoR-0 與菲萊在台服模式查得到凋亡損傷。

## 不在範圍內

- 台服有標、陸服沒標的術語反過來補到陸服:目前沒有這種情況(cmp.cjs 輸出的「台服多出」為 0,見[其他備註](#其他備註)),而且陸服是比對的主要來源。
- 補充關鍵字:兩服各自比對比對字串,不照陸服補。
- 模組階段:兩服都用陸服文字,本來就一致。
- 介面改動:補上的字和官方標記的字看起來一樣。
- 術語比對清單的內容不變:兩服都沒標的漏標(例如特性的「可以造成元素損傷」)仍靠它補。

## 其他備註

- 這份規格取代[術語補標與漏標稽核](.scratch/term-gap-fill/spec.md)「不在範圍內」裡的「同名術語的補標」與「台服沿用陸服標記的機制」兩條。那份規格在「用什麼機制補上遊戲沒標的術語?」曾考慮「台服沿用陸服標記,加上術語純文字比對清單」,當時因為要維護兩套機制而沒選;補完之後只剩同名術語補不到,所以重新決定。
- 「只剩 2 段」:scratchpad 的一次性腳本 cmp.cjs(在 repo 根執行 `node <scratchpad>/cmp.cjs .`)讀建好的幹員檔,列出台服與陸服不一致的階段,並把陸服有、台服沒標的術語分成「台服純文字有該名稱」與「沒有」。2026-11-09 的輸出:不一致階段 2;可補 2(PhonoR-0 天賦 1 的 ba.dt.apoptosis2、菲萊天賦 1 的 ba.dt.apoptosis);補不了(找不到名稱)0;台服多出 0。
- 全庫模擬:scratchpad 的 mkbi2.cjs 把建置索引複製成依本規格改寫階段組成的版本,sim2.ts 用同一份資料和現行版各建一次比對(在 repo 根依序執行 `node <scratchpad>/mkbi2.cjs`、`npx tsx <scratchpad>/sim2.ts F:/AiProject/ark-keyword`)。2026-11-09 的結果:照陸服補標 29 個階段、34 個標記,其中 27 個階段現在本來就由比對清單補上,結果相同;台服文字有差異、以及由不一致變一致的階段都只有 PhonoR-0 與菲萊的天賦 1;陸服文字沒有差異;新警告 0 則;疑似漏標消失 2 筆,就是上述已知清單那 2 筆。
